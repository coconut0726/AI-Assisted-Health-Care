主要 Prompt 修改
1. 第一阶段只分解 Steps / atomic Actions / dependencies；第二阶段按 Action 生成规格。
   一次看目标并检查多个特征合并为一次检查；入袋/封口分开；初始/最后洗手保持独立。
   “remove；if sticks，soak before lifting”不能误成 remove->soak->再lift。
   条件护士通知不因最后出现而依赖整套换药结束。
2. 保留 preconditions、postconditions、error criteria、evidence，不新增 execution_constraints。
   操作方式和持续禁忌放 error criteria，正向 compliance_condition 与 violation_condition 配对。
   没检测到错误，不等于已经证明合规。跨动作同一禁忌只定义一次。
3. 精简掉重复的 VQA/compliance question 字段，未来由 condition / compliance_condition
   直接构造正向问题，减少改写丢条件或 yes 极性反转。暂去掉非主线 skip risk / in-progress；
   原来的完整草案仍保留在历史版本中。
4. 区分末态可见、动作发生、物料性质成立与临床/目标状态成立。
   手看起来干净不证明洗过；棉签在旁边不证明用过；戴手套不证明手套干净。
   不补写时长、温度、厚度、松紧阈值、额外护理技巧或未提供的专家先验。
5. 目标原本异常不自动属于操作者错误。检查到 cut 发红/肿胀/渗漏，不能直接
   归类为 Technique Error，也不能凭此自行补写新的护理处理动作。

图中未擅加 source 未指明的 soap/water。

这不是单次稳定性或跨任务泛化实验；有反馈的样例也不算独立的一次成功测试。
两阶段指逻辑阶段，实验第二阶段按小批次 Action 请求，因此 HTTP 请求多于两次。
所有模型响应、输入、prompt、schema、版本及校验都保留；未手改响应掩盖问题。
本次 schema 因 nurse_prior 为空，额外禁止 expert_prior；将来若提供真实先验，
应按输入恢复该来源枚举。此次并未更改正式工具如何处理先验。

下一步建议
这轮证据支持继续采用精简的两阶段表示，但不足以批准自动生成结果直接驱动放行。
Order/Missing 宜在后续代码中从审查后的 DAG 与真实事件记录确定性推导，减少让 LLM
再叙述一遍图规则导致的丢边、重复和漏条件。此处仅建议，尚未修改运行时代码。
当前 5 秒单张 after_step RGB 不提供 before、连续过程、完整历史或人工确认通道；
需要这些证据的规格必须保持 unknown/human_required。生成更多字段不会创造证据。
gently/thin/loosely/cool 的操作性定义仍须领域专家决定，不能由 prompt 编造。
应先审阅这些失败点和最新草案，再决定 parser/session/验证流程的代码迁移。
